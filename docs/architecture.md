# Architecture and safety boundaries

`packages/protocol` defines version 1 messages, validators and UTF-16 offset edits. `packages/core` owns one Session per explicit document URI, a clock-injected 15,000 ms scheduler, graph identities, layout and recoverable conflict checkpoints. It imports no editor or UI APIs. Its `EditorAdapter` send contract and transport-independent hooks allow future editors. `packages/verilog` translates source into a deliberately limited AST and deterministic RTL graph projection. `packages/core/service.ts` hosts the authenticated loopback WebSocket link. Electron owns this service; shutting down its separate window disconnects the editor.

The renderer has no filesystem, process, WebSocket or Node access. Its preload exposes only state subscription and checked graph commands. Navigation and additional windows are blocked. The service listens on an OS-assigned port on 127.0.0.1; `.hdlgraph/connection.json` contains a random per-session credential. Browser Origin requests, invalid versions, unshared documents, out-of-workspace URIs, oversized messages and unsolicited sync-origin claims are rejected. One VS Code adapter can connect at once; multiple explicitly shared documents have independent sessions. This is a same-user local application, not a defense against another process already able to read your workspace.

VS Code sends complete **in-memory** snapshots, including unsaved work. Source files are never read or written by the graph service. A patch includes a source version and SHA-256 hash. The extension rechecks both, independently parses the original buffer, and accepts only non-overlapping supported operator/literal/range/selector spans. The resulting module must parse and project safely. It applies one native `WorkspaceEdit` to the live URI and recognizes exactly one expected change event, then sends a one-use acknowledgment containing the resulting buffer. User undo is a new user edit. The core commits only a matching acknowledgment; mismatch, timeout and disconnect preserve checkpoints and show a status. Reconnect explicitly shares the latest buffer again; it never replays old patches.

All text and semantic graph changes restart inactivity. Layout movement also restarts it without changing semantic authority. Viewport pan/zoom saves immediately. A separate acknowledgment timeout cannot be canceled by layout activity. Conflicts remain locked until explicit document reopening; movement cannot clear them or replay old edits. Superseding pending work creates local recovery JSON before it is discarded. Graph-last edits reparse the current buffer and replace selected spans; unrelated newer text is preserved. Recursive semantic operand signatures prevent matching different subexpressions merely because they have the same display labels. Invalid source, changed operands or unsafe grouping refuse patches. Structural IDs use module, target, expression path and component kind, never line numbers. Committed removal prunes IDs/manual coordinates; recreation gets new IDs. Pending graph edits are part of published state and survive renderer reloads.

Layout files are `.hdlgraph/layout-<sha256(document URI)>.json` with schema version, structural identity mapping, node positions and viewport. Writes use a temporary file and rename. New nodes receive dependency-depth columns from left to right without moving manually placed nodes. Cycles fail visibly. Recovery files contain the URI, revision, full text and pending graph edits; copy text from them into VS Code to restore. There is no automatic recovery replay or restore command yet. Keep `.hdlgraph/` out of version control; it includes source snapshots and session credentials.

## Parser decision

Reviewed the existing [tree-sitter-verilog parser's package manifest](https://github.com/tree-sitter/tree-sitter-verilog/blob/master/package.json) and [README](https://github.com/tree-sitter/tree-sitter-verilog/blob/master/README.md). It provides a broad SystemVerilog grammar under MIT and includes native Node bindings through `node-gyp-build`, with a WASM build alternative. It remains a strong expansion candidate. For this milestone, adopting that backend would add native/prebuilt binding or WASM packaging validation while still requiring a strict editable-subset projection. This was a source/package evaluation, not a runtime benchmark or compatibility test of that parser.

Evaluated the installed Chevrotain toolkit's tokenization API and position tracking for this MVP. It supplies the production lexer (including comment skipping and exact JavaScript UTF-16 token offsets); a small recursive-descent module/declaration adapter and Pratt expression parser implement only our advertised grammar. This is not regex-based source replacement or an attempt at a full Verilog grammar. Chevrotain's general CST parser would still require writing the same restricted grammar; the explicit subset parser keeps error/refusal behavior small and testable. A full Verilog grammar/parser integration remains a future adapter replacement, not a claimed feature. Comments and whitespace are untouched source slices, never regenerated AST output. Unsupported syntax rejects the complete projection, retaining the last valid graph and an explanatory panel.

## Layout decision

Electron + React + React Flow provide independent desktop UI, keyboard selection/movement, dragging, pan and zoom. The canvas holds local drag state during a gesture instead of resetting it from service snapshots. The smoke test feeds Chromium real pointer-down/move/up events in a focused window and verifies persisted movement. A small deterministic dependency-depth layout replaces ELK. It is not a crossing-minimizing layout engine. No connectivity is inferred from coordinates. Window bounds are saved on close, checked against connected displays and clamped on-screen when a monitor disappears. Node insertion, deletion, connection editing, synthesis and simulation remain unavailable.

## Construction transactions

The desktop projects a separate pending graph while the committed graph remains tied to the acknowledged editor buffer. Each action resolves node IDs to structural AST keys and plans bounded source insertions or replacements. A piece table composes edits inside newly added code into minimal spans against the original buffer. A batch contains at most 100 actions and retains up to 50 pending history frames.

Structural patches include their ordered source actions. After checking the exact live version and SHA, the VS Code adapter independently replays the actions through the parser/projector and compares the resulting composed edits before one WorkspaceEdit. Parsing alone is not sufficient authorization for a structural rewrite. Comment deletion, cycles and ambiguous shared-declaration removal are refused.

Newer source text supersedes pending structure and saves the complete preview and action log to recovery. Invalid source keeps the last committed graph visible; construction waits for a valid synchronized source. ACK/conflict locks apply to history as well as circuit changes. Commit transfers preview identities and retains manually placed coordinates. Native editor Undo reverses the entire committed batch.
