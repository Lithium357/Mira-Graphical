# Architecture and safety boundaries

## Native HDL frontends

`packages/verilog` handles the documented Verilog/SystemVerilog subset; `packages/vhdl` tokenizes and parses native VHDL into the shared expression/hierarchy model with explicit native types, widths and conversion nodes. VHDL uses its own arithmetic sizing and source emitter. Common projection, layout, hierarchy, simulation and synchronization operate on that model. Source content selects the frontend, while the adapter accepts `.v`, `.sv`, `.vhd` and `.vhdl` documents.

Construction proofs replay native source actions in the editor's bundled parser before applying a patch. VHDL declarations and architecture statements use separate insertion anchors; entity export includes its IEEE context. Clipboard/import actions reject mixed HDL families. Unsupported syntax is refused before a new graph is committed. Neither frontend claims full language-standard coverage.

`packages/protocol` defines version 1 messages, validators and UTF-16 offset edits. `packages/core` owns one Session per explicit document URI, a clock-injected 15,000 ms scheduler, graph identities, layout and recoverable conflict checkpoints. It imports no editor or UI APIs. Its `EditorAdapter` send contract and transport-independent hooks allow future editors. `packages/verilog` translates source into a deliberately limited AST and deterministic RTL graph projection. `packages/core/service.ts` hosts the authenticated loopback WebSocket link. Electron owns this service; shutting down its separate window disconnects the editor.

The renderer has no filesystem, process, WebSocket or Node access. Its preload exposes only state subscription and checked graph commands. Navigation and additional windows are blocked. The service listens on an OS-assigned port on 127.0.0.1; `.hdlgraph/connection.json` contains a random per-session credential. Browser Origin requests, invalid versions, unshared documents, out-of-workspace URIs, oversized messages and unsolicited sync-origin claims are rejected. One VS Code adapter can connect at once; multiple explicitly shared documents have independent sessions. This is a same-user local application, not a defense against another process already able to read your workspace.

VS Code sends complete **in-memory** snapshots, including unsaved work. Source files are never read or written by the graph service. A patch includes a source version and SHA-256 hash. The extension rechecks both, independently parses the original buffer, and accepts only non-overlapping supported operator/literal/range/selector spans. The resulting module must parse and project safely. It applies one native `WorkspaceEdit` to the live URI and recognizes exactly one expected change event, then sends a one-use acknowledgment containing the resulting buffer. User undo is a new user edit. The core commits only a matching acknowledgment; mismatch, timeout and disconnect preserve checkpoints and show a status. Reconnect explicitly shares the latest buffer again; it never replays old patches.

All text and semantic graph changes restart inactivity. Layout movement also restarts it without changing semantic authority. Viewport pan/zoom saves immediately. A separate acknowledgment timeout cannot be canceled by layout activity. Conflicts remain locked until explicit document reopening; movement cannot clear them or replay old edits. Superseding pending work creates local recovery JSON before it is discarded. Graph-last edits reparse the current buffer and replace selected spans; unrelated newer text is preserved. Recursive semantic operand signatures prevent matching different subexpressions merely because they have the same display labels. Invalid source, changed operands or unsafe grouping refuse patches. Structural IDs use module, target, expression path and component kind, never line numbers. Committed removal prunes IDs/manual coordinates; recreation gets new IDs. Pending graph edits are part of published state and survive renderer reloads.

Layout files are `.hdlgraph/layout-<sha256(document URI)>.json` with schema version, structural identity mapping, node positions and viewport. Writes use a temporary file and rename. New nodes receive dependency-depth columns from left to right without moving manually placed nodes. Cycles fail visibly. Recovery files contain the URI, revision, full text and pending graph edits; copy text from them into VS Code to restore. There is no automatic recovery replay or restore command yet. Keep `.hdlgraph/` out of version control; it includes source snapshots and session credentials.

## Parser decision

Reviewed the existing [tree-sitter-verilog parser's package manifest](https://github.com/tree-sitter/tree-sitter-verilog/blob/master/package.json) and [README](https://github.com/tree-sitter/tree-sitter-verilog/blob/master/README.md). It provides a broad SystemVerilog grammar under MIT and includes native Node bindings through `node-gyp-build`, with a WASM build alternative. It remains a strong expansion candidate. For this milestone, adopting that backend would add native/prebuilt binding or WASM packaging validation while still requiring a strict editable-subset projection. This was a source/package evaluation, not a runtime benchmark or compatibility test of that parser.

Evaluated the installed Chevrotain toolkit's tokenization API and position tracking for this MVP. It supplies the production lexer (including comment skipping and exact JavaScript UTF-16 token offsets); a small recursive-descent module/declaration adapter and Pratt expression parser implement only our advertised grammar. This is not regex-based source replacement or an attempt at a full Verilog grammar. Chevrotain's general CST parser would still require writing the same restricted grammar; the explicit subset parser keeps error/refusal behavior small and testable. A full Verilog grammar/parser integration remains a future adapter replacement, not a claimed feature. Comments and whitespace are untouched source slices, never regenerated AST output. Unsupported syntax rejects the complete projection, retaining the last valid graph and an explanatory panel.

## Layout decision

Electron + React + React Flow provide independent desktop UI, keyboard selection/movement, dragging, pan and zoom. The canvas holds local drag state during a gesture instead of resetting it from service snapshots. The smoke test feeds Chromium real pointer-down/move/up events in a focused window and verifies persisted movement. A small deterministic dependency-depth layout replaces ELK. It is not a crossing-minimizing layout engine. No connectivity is inferred from coordinates. Window bounds are saved on close, checked against connected displays and clamped on-screen when a monitor disappears. Construction and connection actions use the guarded transaction layer below. Synthesis and sequential simulation remain unavailable.

## Construction transactions

The desktop projects a separate pending graph while the committed graph remains tied to the acknowledged editor buffer. Each action resolves node IDs to structural AST keys and plans bounded source insertions or replacements. A piece table composes edits inside newly added code into minimal spans against the original buffer. A batch contains at most 100 actions and retains up to 50 pending history frames.

Structural patches include their ordered source actions. After checking the exact live version and SHA, the VS Code adapter independently replays the actions through the parser/projector and compares the resulting composed edits before one WorkspaceEdit. Parsing alone is not sufficient authorization for a structural rewrite. Comment deletion, cycles and ambiguous shared-declaration removal are refused.

Newer source text supersedes pending structure and saves the complete preview and action log to recovery. Invalid source keeps the last committed graph visible; construction waits for a valid synchronized source. ACK/conflict locks apply to history as well as circuit changes. Commit transfers preview identities and retains manually placed coordinates. Native editor Undo reverses the entire committed batch.

## Module libraries and editing tools

The lexer partitions a shared document into complete module definitions and retains absolute source spans. Named-port instance interfaces are resolved against the document library; recursion, incomplete bindings, conflicting output drivers and conservative instance feedback cycles are rejected. The active definition is session state. Every transaction carries its module scope; the editor independently resolves the same scope while replaying it. Identity/layout storage retains keys from inactive definitions and module-specific viewports. Navigation is read-only and requires pending edits to synchronize or be discarded.

Explicit import reads another already-shared session's acknowledged in-memory snapshot, extracts the selected definition and its transitive dependencies and appends a validated copied library. It never opens arbitrary files or changes the source session. Imported modules are local copies; duplicate names are refused. A pending source/draft cannot be exported.

Clipboard payloads contain bounded declarations, supported expression fragments and named instance bindings. Paste creates unique names and remaps selected internal references, preserving valid external dependencies. The planner rejects statement/comment/dotted-name injection and reparses the entire result. Selecting an expression copies its result as a wire; selecting a port explicitly preserves its direction. Paste is one pending history action and one composed native source transaction.

## Durable recovery

Every semantic buffer/draft change checkpoints the live source, version, graph preview and inert action data before publishing state. Layout-only movement does not rewrite the journal. Checkpoints use per-document SHA-256 filenames and atomic UTF-8 temporary-file replacement. Opening a different buffer in a new service session archives its previous checkpoint first. Explicit conflict/discard/disconnect snapshots remain separate history files. A failed checkpoint produces a visible warning without disabling live editing; a corrupt previous checkpoint is left intact rather than silently replaced.

`RecoveryStore` bounds snapshot sizes, validates source workspace membership, rejects path traversal and symbolic links, and lists at most 100 recent files. List descriptions have an aggregate 8 MB read budget; selecting a file validates it independently. The UI truncates only its on-screen preview at 100,000 characters; copy/open uses the complete bounded text. Snapshots are never automatically deleted or executed. These are application-crash checkpoints, not a power-loss or disk-failure guarantee.

Recovery IPC accepts an opaque file identifier, never an arbitrary filesystem path. Open/compare requests carry the selected snapshot's SHA-256 fingerprint; a live checkpoint that changed after preview must be selected again. The authenticated editor link can request a separate untitled document or a native diff; comparisons require the current source to be explicitly shared. The extension does not apply a WorkspaceEdit, save a source file, or share the recovered document. Invalid/unsupported HDL can therefore still be inspected and recovered. The renderer can also copy recovery text through the existing clipboard capability without an editor connection.

The companion advertises a bounded `recovery-review` capability in its existing protocol-v1 handshake. Older adapters can still share/edit ordinary documents; recovery-open requests give an explicit upgrade error rather than disappearing silently. Clipboard commands await the native clipboard operation before reporting completion.

## Diagnostics and simulation

Projection emits warnings independently of parse failures. Arithmetic and mux nodes inherit unsigned destination context; concat parts and slices remain self-determined. Driver widths and socket widths generate extension/truncation warnings, while multi-bit selectors report nonzero truth rather than pretending to truncate the condition.

The evaluator runs in the core with no renderer execution or source writes. Values contain a BigInt value, known-bit mask and bounded width. Input vectors are validated; arithmetic is masked at its context width, and unknown arithmetic is pessimistic. Bitwise operations and conditional merging retain resolvable bits. Declared ascending slices use distance from the declared least-significant index. Each instance is evaluated with its named inputs, caches its output map and exposes hierarchical signal paths for traces. Unknown undriven nets are modeled as x, not as a separate high-impedance state. Width/signal/expansion bounds prevent unbounded masks or elaboration.

The renderer stores at most 64 sampled vectors for 16 watched signals and overlays the latest node values. Source/draft revisions or semantic structure changes invalidate pending evaluation results and reset traces. Viewport/layout-only updates preserve them. CSV export is an explicit clipboard command; no source data is sent over the network. Official VSIX packaging is a separate development script with a five-source-file allowlist; signing and Marketplace publishing are not performed.

## Clocked elaboration and reconnection

Hierarchy is elaborated into independent path-qualified nets/registers for simulation and combinational-cycle validation. Register Q breaks same-cycle dependencies; all scheduled nonblocking/signal updates commit together, and event propagation settles in at most 64 delta rounds. Inputs to Verilog edge blocks remain scalar module ports. VHDL rising/falling functions use known transitions; asynchronous reset activation is modeled separately.

Ordered Verilog blocking assignments are lowered with explicit intermediate width/type boundaries. Branch completeness is checked before graph publication; synthetic case predicates do not become editable token spans. Register construction emits individual source processes; rewiring updates exact D/clock/reset spans, including VHDL sensitivity lists. Shared process removal is refused.

Companion retries reread the authenticated descriptor and resend fresh in-memory snapshots. Transport generations and capped backoff prevent stale retries from taking ownership after disconnect. Pending patches are never replayed. Only previously explicitly shared open documents in a trusted matching workspace can resume after editor reload.
