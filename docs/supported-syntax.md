# Supported HDL subsets

Open `.v`, `.sv`, `.vhd` or `.vhdl` documents explicitly through the companion extension. Source content selects the native parser. Files may contain their own definitions, copy imports, or explicitly link other shared buffers through View → Project sources. Linked projects are read-only in the graph; see [project and test workflows](simulation-tests.md). Verilog and SystemVerilog share a family; VHDL definitions and clipboard fragments stay within the VHDL family. Mixed-language elaboration is unsupported.

## SystemVerilog

Module-local `typedef enum` and inline enum variables support named states in expressions, `case` choices, combinational next-state logic and clocked registers. Try [the enum FSM example](../fixtures/enum-fsm.sv). The circuit displays enumerator names; simulation uses their declared encodings. Assert reset and sample, deassert reset, then use **Step clk** to advance the machine.

For example, `typedef enum logic [1:0] { IDLE=2'b00, RUN, DONE=2'b11 } state_t; state_t state, next_state;` declares two typed state variables. Unspecified member encodings increment from the previous member, starting at zero. The default base is signed 32-bit `int`; explicit `int`, `logic` and `reg` bases accept signed/unsigned qualifiers. Packed logic/reg widths are bounded to 4096 bits and each enum to 128 members. Explicit encodings must be decimal or sized literals, known, unique and representable in the base; sized literals must match its width. Negative decimal encodings require a signed base.

Assignments to enum variables require members or variables of the same enum type, including same-type ternary arms. Numeric coercions, enum casts/methods, arithmetic initializers, `bit` bases, enum arrays/ranges, package types and enum-typed ports remain unsupported. Edit enum encodings in HDL: individual named uses are read-only graph constants. Copying an expression into a plain wire materializes sized numeric constants, preserving its meaning across scopes. View → State machines derives a state/transition view with simulation highlighting. Diagram editing remains unsupported. Architecture-local VHDL enums are described below.

The Verilog subset also accepts `logic`/`reg`, optional `signed`/`unsigned`, and context-sized `'0`/`'1`. `always_comb`, `always @*` and `always @(*)` accept ordered blocking assignments, nested `begin`/`end`, complete `if`/`else`, defaults followed by conditional overrides, and literal-choice `case` statements. Targets must be declared `logic`/`reg`. Reads of an already assigned temporary preserve its declared width/type; reads before assignment and incomplete paths are rejected as latch/order dependencies. Slicing an ordered temporary still requires a separate continuous wire. Copied ordered expressions use supported explicit size casts (`N'(expression)`) to preserve intermediate widths.

`always_ff` and edge-triggered `always` support the clocked subset below. `case` accepts up to 128 arms of decimal/sized literal choices, comma-separated choices, and an optional default. A combinational case needs a default or prior default assignments. Mixed signed selectors/unsigned choices require a declared unsigned selector wire. Negative labels, `casex`/`casez`, loops, `always_latch`, general event controls, packed structures, interfaces, packages, classes, assertions, signed based literals, parameters and generate remain unsupported. This is a bounded RTL subset, not full language-standard coverage.

## Clocked Verilog/SystemVerilog (0.9.4)

Modules accept `always @(posedge clk or posedge reset)` and `always_ff @(negedge clk or negedge reset)`, with one or two distinct scalar input controls separated by `or` or a comma. Bodies accept whole-register nonblocking (`<=`) assignments, nested blocks, `if`/`else`, and literal-choice `case`, including omitted branches/enable holds. Targets must be `reg` or `logic`, with one driving process. Conditions and right-hand sides read pre-event state; later assignments take priority and all process/instance updates commit together. Unknown procedural conditions take the else path.

Registers appear as D/Q nodes. Q breaks same-cycle dependencies; flattened validation still rejects combinational loops, including feedthrough through a clocked child. Named instances preserve independent register state. Parent simulation exposes hierarchical signals such as `a.q`; opening a child definition starts its own simulation. Mixed-language hierarchy remains unsupported.

The register palette creates individual registers with scalar input clock, optional asynchronous reset/polarity, and a selected data signal. D/clock/reset can be rewired through the graph; VHDL edits update sensitivity lists as well as edge/reset expressions. Shared multi-target control blocks and complex procedural results require HDL edits for structural rewiring/removal. Source-token edits remain guarded, including clocked expressions. Individual registers cannot be copied as combinational fragments; copy their module/entity instance or create another register. Comments and surrounding source remain protected.

Simulation retains registers between samples. Input transitions trigger declared edges, including asynchronous reset while the clock is held. **Step clk** pulses a directly bound top-level clock, retaining other inputs; expression-bound clocks can be driven manually through input sampling. All instance updates settle in at most 64 delta cycles; unstable clock/reset networks are refused. Registers start unknown: assert reset and sample, then deassert before stepping. **Restart simulation**, source/module changes clear state; **Clear trace** only clears displayed samples. No timed testbenches, delay controls, internal event controls, blocking clocked assignments, slice writes or loops are implemented. Statement nesting is limited to 128; expanded expressions to 8192 nodes/256 levels per module; elaboration/simulation to 4096 signals.

Logical `!`, `&&` and `||` use nonzero truth with unknown propagation and produce an unsigned scalar. Constant replication `{count{expression, ...}}` accepts decimal counts 1–4096, up to 64 parts and at most 4096 resulting bits; parts remain self-determined and explicitly sized. Signed net references retain declaration signedness; selections and concatenations are unsigned.

## VHDL

Architecture-local `type state_t is (idle, running, finished);` declarations and enum signals support same-type assignments, equality conditions, named `case` choices, combinational next-state logic in `process(all)`, and clocked state registers. Names are case-insensitive; each type has 1–128 unique basic-identifier members, represented internally by declaration-order encodings. VHDL enum signals initialize to their leftmost member. Enum casts, arithmetic, slices, concatenations, packages, character-literal members, enum ports and explicit representation attributes remain unsupported. Numeric bit strings cannot be assigned to enum signals. Try [enum-fsm.vhd](../fixtures/enum-fsm.vhd).

`process(all)` accepts defaults, nested `if/elsif/else` and literal/enum `case` alternatives. Cases must cover every member of their enum or include a final `others`. Other case selectors require `others`. Duplicate choices and incomplete assignments are rejected. Reads of a signal assigned by the same combinational process are refused; split signal feedback into separate processes. Complex multi-target procedural blocks require HDL edits for structural rewiring.

VHDL uses native parsing and native source edits. Supported constructs:

- IEEE `std_logic_1164` and `numeric_std` contexts, case-insensitive basic identifiers, entities with `in`/`out` ports and one architecture per entity. Multiple entity/architecture pairs may share a file; each entity precedes its architecture.
- Scalar `std_logic`, constrained ascending/descending `std_logic_vector` and `unsigned` signals and ports; fixed bit and part selections.
- Concurrent assignments, `value when selector = '1' else value`, and named/unnamed `process(all)` blocks with defaults, nested conditionals and complete literal/enum cases.
- Bit literals, binary strings, binary/octal/hex bitstrings, bounded `to_unsigned`, `unsigned`/`std_logic_vector` conversions and qualified expressions, and unsigned `resize`.
- Unsigned `+`, `-`, `*`, matching-type `and`/`or`/`xor`, concatenation with `&`, direct `entity work.name port map (...)` instances with named associations.
- Native construction, rewiring, tie-offs, removal, ports, entity creation, import, copy/paste and simulation. New vector components use `unsigned`; scalar components use `std_logic`. Scalar arithmetic creation is refused; scalar bitwise operations are supported.
- Named or unnamed `process(clk[, reset])` with outer `if rising_edge(clk)`/`falling_edge(clk)`, or asynchronous reset `if reset = '1' then ... elsif rising_edge(clk) then ...`. Active-low reset is supported. Sensitivity lists must name exactly the scalar input clock and optional asynchronous reset. Bodies support signal assignments, scalar `if`/`elsif`/`else` with selectors compared to `'0'`/`'1'`, null statements and literal-choice cases (one choice per arm, optional `others`). Native hierarchy and graph-created registers use the same typed evaluator.

VHDL assignment types and widths must match exactly. Addition/subtraction use the larger operand width; multiplication uses the sum of operand widths. `resize` and conversions are visible graph nodes and are evaluated explicitly. Graph wiring emits conversions/resizes when needed. Graph literal fields accept canonical sized literals or supported native VHDL literal syntax; graph range fields use `[left:right]`, emitted as native `to`/`downto` ranges. Graph editing never translates the document into Verilog.

Generics, packages/other custom types, records, arrays beyond the supported vectors, signed arithmetic, arbitrary sensitivity lists, process variables, incomplete combinational branches, loops, delays, attributes, arbitrary functions and component declarations remain unsupported. Source `x`/`z` values and extended identifiers are unsupported. This subset targets VHDL-2008, without full standard coverage.

A document is limited to 1 million UTF-16 units, 32768 tokens and 64 modules; each module has at most 4096 tokens and expressions have at most 128 recursive levels. Expanded hierarchy is limited to 256 instances and 32 levels. Instance cycle checks conservatively treat each output as dependent on all inputs, so independent-port feedback patterns can be refused. One unsupported definition prevents a complete projection; the last valid graph remains visible.

The graph uses Verilog assignment context for arithmetic/mux result widths. Diagnostics do not rewrite widths. Constants exceeding their explicit width are refused. Simulator values are limited to 4096 bits and the expanded circuit to 4096 signals; undriven nets are represented as unknown rather than distinguishing `z`. Input vectors may contain unknown binary bits. This is not a full four-state, timed HDL simulator. The waveform UI retains 64 sampled vectors and at most 16 watched signals; newly added traces have no historical sample until the next evaluation.

### Explicit signed expressions (0.9.3)

`$signed(expression)` and `$unsigned(expression)` change the interpretation of a self-determined expression without changing its width. The graph shows a single-input cast node. Comparisons use signed ordering when both operands are signed; mixed signed/unsigned operands use unsigned ordering. Assignment width can extend a signed expression using its sign bit. Unknown sign bits remain unknown when extended.

`===` and `!==` compare the supported known/unknown bit patterns and always return a known bit. A procedural `if` with unknown truth selects its `else` arm, while a ternary merges unknown-selected arms. Copied procedural muxes preserve these truth rules and each arm's independent assignment context.

`>>>` uses the left operand's effective type: signed values sign-fill, unsigned values zero-fill. Shift amounts remain self-determined and are interpreted as unsigned bit patterns. `>>` always zero-fills. A ternary expression with unsigned arms can coerce an inner shift to unsigned. For a signed shift feeding the reported ALU's unsigned mux chain, write `$unsigned($signed(OPc) >>> OPd)`; the outer cast isolates the signed shift before the mux interprets its bit pattern as unsigned. Mira flags zero-filling `>>>` operations and does not change your source automatically.

Try `fixtures/alu-int16-signed.v` for the reported source and compare it with the isolated-shift expression above, or `fixtures/alu-int16-clocked.v` for the later ALU and iterative multiplier. Signed net declarations are supported in 0.9.4; signed based literals and other system functions remain unsupported. VHDL retains its documented unsigned type subset.

Structural changes preserve surrounding source and comments. Shared wire declarations and comment-bearing spans require source edits for destructive changes. Ports cannot be removed through the graph. Adding/changing a child interface must leave all existing instances valid. Removing an instance leaves its output wires declared and visibly undriven. Copies preserve supported expressions and reject statement/comment injection. Nested expressions need named results to be shared/copied individually.

The extension replays construction proofs against the exact version/hash before one native WorkspaceEdit. Pending Undo/Redo is local to a batch; after synchronization use native editor Undo. Navigation/import/simulation do not bypass ACK/conflict locks. Recovery restore is manual. IDs use module/structural paths and kind; committing removal discards the old active-module identity while preserving other module views.

## Verilog/SystemVerilog ALU operators (0.9.0)

Unsigned `<<` and `>>`, `==`, `!=`, `<`, `<=`, `>` and `>=`, and unary bitwise NOT `~` are supported in source, construction, wiring, clipboard and local simulation. Comparisons produce one bit and compare unsigned operands at their common width. Shifts use the left operand/result context width; the shift amount is self-determined. NOT follows its operand/result context and has one input socket. Verilog precedence is preserved; token edits that change grouping are refused. VHDL retains its separately documented typed operator subset.

Try `fixtures/alu-int16.v` and select **ALU_INT16**. The empty **ALU_FP16** definition intentionally has an undriven output; it does not implement floating-point arithmetic.
