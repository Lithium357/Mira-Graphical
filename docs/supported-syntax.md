# Supported HDL subsets

Open `.v`, `.sv`, `.vhd` or `.vhdl` documents explicitly through the companion extension. Source content selects the native parser. Files contain their own definitions; imports copy definitions from other explicitly shared documents. Verilog and SystemVerilog share a family; VHDL definitions and clipboard fragments stay within the VHDL family. Mixed-language elaboration is unsupported.

## SystemVerilog

The Verilog subset below also accepts `logic`/`reg` declarations, optional `unsigned`, and context-sized `'0`/`'1` literals. `always_comb` accepts one blocking assignment, a `begin`/`end` block of independent blocking assignments, or one complete `if`/`else` assigning the same target. Branches may use single-statement `begin`/`end`. Every procedural target must be declared `logic`/`reg`. A block cannot read a signal it writes; procedural ordering and latch semantics are refused. Copied procedural muxes become equivalent conditional expressions.

`always_ff`, `always_latch`, general `always`, clocks/events, nonblocking assignments, incomplete conditionals, loops, case statements, packed structures, interfaces, packages, classes, assertions, signed declarations/literals, parameters and generate remain unsupported. Explicit `$signed`/`$unsigned` expression casts are supported. This is combinational RTL support, not the full SystemVerilog design or verification language.

## VHDL

VHDL uses native parsing and native source edits. Supported constructs:

- IEEE `std_logic_1164` and `numeric_std` contexts, case-insensitive basic identifiers, entities with `in`/`out` ports and one architecture per entity. Multiple entity/architecture pairs may share a file; each entity precedes its architecture.
- Scalar `std_logic`, constrained ascending/descending `std_logic_vector` and `unsigned` signals and ports; fixed bit and part selections.
- Concurrent assignments, `value when selector = '1' else value`, and unnamed `process(all)` blocks containing independent signal assignments or one complete `if selector = '1' then ... else ... end if` assigning the same target.
- Bit literals, binary strings, binary/octal/hex bitstrings, bounded `to_unsigned`, `unsigned`/`std_logic_vector` conversions and qualified expressions, and unsigned `resize`.
- Unsigned `+`, `-`, `*`, matching-type `and`/`or`/`xor`, concatenation with `&`, direct `entity work.name port map (...)` instances with named associations.
- Native construction, rewiring, tie-offs, removal, ports, entity creation, import, copy/paste and simulation. New vector components use `unsigned`; scalar components use `std_logic`. Scalar arithmetic creation is refused; scalar bitwise operations are supported.

VHDL assignment types and widths must match exactly. Addition/subtraction use the larger operand width; multiplication uses the sum of operand widths. `resize` and conversions are visible graph nodes and are evaluated explicitly. Graph wiring emits conversions/resizes when needed. Graph literal fields accept canonical sized literals or supported native VHDL literal syntax; graph range fields use `[left:right]`, emitted as native `to`/`downto` ranges. Graph editing never translates the document into Verilog.

Generics, packages/custom types, records, arrays beyond the supported vectors, signed arithmetic, clocked processes, sensitivity lists other than `all`, named processes, process variables, incomplete branches, loops/case, delays, attributes, arbitrary functions and component declarations are unsupported. Source `x`/`z` values and extended identifiers are unsupported. Unsupported syntax stops projection and preserves the last valid graph. This subset targets VHDL-2008 syntax, without full standard coverage.

A document is limited to 1 million UTF-16 units, 32768 tokens and 64 modules; each module has at most 4096 tokens and expressions have at most 128 recursive levels. Expanded hierarchy is limited to 256 instances and 32 levels. Instance cycle checks conservatively treat each output as dependent on all inputs, so independent-port feedback patterns can be refused. One unsupported definition prevents a complete projection; the last valid graph remains visible.

The graph uses Verilog assignment context for arithmetic/mux result widths. Diagnostics do not rewrite widths. Constants exceeding their explicit width are refused. Simulator values are limited to 4096 bits and the expanded circuit to 512 signals; undriven nets are represented as unknown rather than distinguishing `z`. Input vectors may contain unknown binary bits. This is not a full four-state, timed HDL simulator. The waveform UI retains 64 sampled vectors and at most 16 watched signals; newly added traces have no historical sample until the next evaluation.

### Explicit signed expressions (0.9.3)

`$signed(expression)` and `$unsigned(expression)` change the interpretation of a self-determined expression without changing its width. The graph shows a single-input cast node. Comparisons use signed ordering when both operands are signed; mixed signed/unsigned operands use unsigned ordering. Assignment width can extend a signed expression using its sign bit. Unknown sign bits remain unknown when extended.

`===` and `!==` compare the supported known/unknown bit patterns and always return a known bit. A procedural `if` with unknown truth selects its `else` arm, while a ternary merges unknown-selected arms. Copied procedural muxes preserve these truth rules and each arm's independent assignment context.

`>>>` uses the left operand's effective type: signed values sign-fill, unsigned values zero-fill. Shift amounts remain self-determined and are interpreted as unsigned bit patterns. `>>` always zero-fills. A ternary expression with unsigned arms can coerce an inner shift to unsigned. For a signed shift feeding the reported ALU's unsigned mux chain, write `$unsigned($signed(OPc) >>> OPd)`; the outer cast isolates the signed shift before the mux interprets its bit pattern as unsigned. Mira flags zero-filling `>>>` operations and does not change your source automatically.

Try `fixtures/alu-int16-signed.v` for the reported source and compare it with the isolated-shift expression above. Signed net declarations, signed based literals and other system functions remain unsupported. VHDL retains its documented unsigned type subset.

Structural changes preserve surrounding source and comments. Shared wire declarations and comment-bearing spans require source edits for destructive changes. Ports cannot be removed through the graph. Adding/changing a child interface must leave all existing instances valid. Removing an instance leaves its output wires declared and visibly undriven. Copies preserve supported expressions and reject statement/comment injection. Nested expressions need named results to be shared/copied individually.

The extension replays construction proofs against the exact version/hash before one native WorkspaceEdit. Pending Undo/Redo is local to a batch; after synchronization use native editor Undo. Navigation/import/simulation do not bypass ACK/conflict locks. Recovery restore is manual. IDs use module/structural paths and kind; committing removal discards the old active-module identity while preserving other module views.

## Verilog/SystemVerilog ALU operators (0.9.0)

Unsigned `<<` and `>>`, `==`, `!=`, `<`, `<=`, `>` and `>=`, and unary bitwise NOT `~` are supported in source, construction, wiring, clipboard and local simulation. Comparisons produce one bit and compare unsigned operands at their common width. Shifts use the left operand/result context width; the shift amount is self-determined. NOT follows its operand/result context and has one input socket. Verilog precedence is preserved; token edits that change grouping are refused. VHDL retains its separately documented typed operator subset.

Try `fixtures/alu-int16.v` and select **ALU_INT16**. The empty **ALU_FP16** definition intentionally has an undriven output; it does not implement floating-point arithmetic.
